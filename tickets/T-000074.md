# T-000074: Fix Video Studio LLM Script Generation & API Key Failover Resilience

## 1. Context & Problem
In the Video Studio, clicking "Generate Script" frequently failed with `500 Internal Server Error: Failed to generate script from LLM`.
Root causes identified:
1. **Google API 503 & JSON Mode Incompatibility**: Google's OpenAI-compatible endpoint returned 503 when passed `response_format={"type": "json_object"}`. When calling without `response_format`, Google returned markdown-wrapped JSON cleanly in under 2 seconds.
2. **HTTP Client Timeout**: `httpx.Client()` in `backend/core/llm.py` lacked explicit timeouts (defaulted to 5.0s), aborting long storyboard completions.
3. **Missing Logger & Unhandled OpenRouter Reasoning**: In `backend/api/video.py`, `logger` was undefined, throwing `NameError` if parsing failed. In `backend/core/llm.py`, reasoning models on OpenRouter placed thinking output in `reasoning` or had `content` formatted as Markdown blocks with think tags.
4. **Scene Overload**: The prompt previously asked for 10-12 scenes for 60 seconds, which frequently exceeded token limits.
5. **No Fallback**: If upstream LLMs were down, `plan_video_script` raised a fatal 500 error instead of gracefully falling back.

## 2. Changes Delivered
1. **`backend/core/llm.py` Resilience**:
   - Configured `httpx.Client(verify=certifi.where(), timeout=httpx.Timeout(60.0, connect=10.0))` and `max_retries=0` on OpenAI client instances.
   - For Google provider, if `response_format={"type": "json_object"}` returns 503, 400, or unsupported, automatically retries without `response_format`.
   - On transient errors (503/429/overload), limits retries to 1 fast attempt (0.8s) before immediately failing over to the secondary configured provider (`openrouter`).
   - OpenRouter provider safely handles `None` models and reasoning token extraction.
   - Enhanced `safe_json_loads` to strip `<think>...</think>` tags and allow control characters with `strict=False`.
2. **`backend/api/video.py` Script Planning**:
   - Imported `logger = logging.getLogger(__name__)`.
   - Rebalanced scene count to 5-7 focused beats for a 60-second video (~9-10s per beat), matching educational production standards (Veritasium/3Blue1Brown style) and fitting cleanly within token budgets.
   - Added `_generate_fallback_storyboard` to ensure the Video Studio UI never crashes with 500 if all upstream LLMs are unreachable.
   - Added graceful handling to `regenerate_single_scene`.

## 3. Verification
- Direct end-to-end Python test of `plan_video_script` for `photosynthesis`: successfully generated 6 pedagogical scenes with durations, visual concepts, and voiceover narrations.
- Direct test of `regenerate_single_scene`: successfully updated scene beat and narration.
- `muontickets/mt.py validate`: passed with 0 errors.
- Pytest test suite verified.
