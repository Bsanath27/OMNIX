## Goal
Remove hardcoded dummy labels (`LEARNING MODULE • {archetype}`, `• PART 1 // Principle 1 // ...`) from `backend/tools/slides/slide_tool.py` and implement native high-resolution image downloading and embedding using `python-pptx` to transform OMNIX's internal slide generator into a professional, production-quality presentation tool.

## Context & Diagnosis
- Inspection of `output/test_slides/omnix_presentation_ai_pipeline_demo.pptx` revealed that OMNIX's internal `slide_tool.py` generated slides with dummy metadata strings (`LEARNING MODULE • HERO STAT`, `• PART 1 // Principle 1 // ...`) instead of clean slide titles and pedagogical content.
- Furthermore, `slide_tool.py` contained zero image handling logic (0 picture shapes, only colored rectangles).
- In contrast, the full-stack engine (`google_1794983581.pptx` and `openrouter_1794984004.pptx`) embedded real 500–820 KB biological diagrams and clean slide typography.

## Acceptance Criteria
- [ ] Remove all hardcoded synthetic prefixes in `backend/tools/slides/slide_tool.py`:
  - Eliminate `p_badge.text = f"LEARNING MODULE • {slide_data.archetype.replace('_', ' ').upper()}"`. Replace with dynamic chapter topic or subject badge (e.g. `BIOLOGY • GRADE 9`).
  - Eliminate `• PART {i+1} // Principle {i+1} // ` in card titles. Use the actual concept title generated by the LLM.
- [ ] Add native image embedding in `slide_tool.py`:
  - Add optional `image_url` / `image_prompt` fields to `SlideContent`.
  - Fetch images from the local image bridge (`http://localhost:8088/v1/images/generations`) or cached assets.
  - Insert images into slide layouts using `slide.shapes.add_picture(image_stream, left, top, width, height)`.
- [ ] Support side-by-side split layouts in `slide_tool.py`: Left panel for diagram/image, right panel for structured bullet points and key takeaways.
- [ ] Verify generated presentation produces clean typography, zero dummy labels, and at least one high-res diagram per content slide.

## Implementation Plan
1. Update `SlideContent` schema in `backend/tools/slides/slide_tool.py` to accept `image_url: Optional[str]` and `image_prompt: Optional[str]`.
2. Refactor layout renderers (`_render_hero_stat`, `_render_card_grid_3`, etc.) to remove debug strings and add split image/text layouts.
3. Integrate with the local image bridge (`scripts/pollinations_image_bridge.py`) during slide compilation.
4. Test and verify compilation to `output/test_slides/`.
