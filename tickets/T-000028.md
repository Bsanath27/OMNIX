## Goal
Expose unified FastAPI slide generation and PPTX/PDF export proxy endpoints in OMNIX that communicate seamlessly with the local Presenton engine, managing container lifecycle and direct asset downloads.

## Acceptance Criteria
- [ ] Implement backend proxy router in `src/omnix/api/routes/presentation_engine.py`:
  - `POST /api/slides/v2/generate`: Proxies presentation generation request to Presenton `POST /api/v1/ppt/presentation/generate` with timeout resilience and streaming progress.
  - `POST /api/slides/v2/{id}/export`: Triggers Presenton export `POST /api/v1/ppt/presentation/{id}/export` and streams the resulting `.pptx` or `.pdf` file to the client.
  - `GET /api/slides/v2/health`: Verifies both Presenton container (`http://localhost:5001`) and Image Bridge (`http://localhost:8088`) status.
- [ ] Automatic container lifecycle check: On OMNIX server startup, check if `presenton` docker container and image bridge are running; log instructions or auto-start if configured.
- [ ] Store generated presentation metadata and exported PPTX paths in OMNIX project storage (`output/presentations/{project_id}/`).
- [ ] Add unit and integration tests verifying generation and PPTX download via OMNIX API.

## Implementation Plan
1. Create `src/omnix/services/presentation_bridge.py` encapsulating HTTP calls to Presenton and the image bridge.
2. Register router in `src/omnix/main.py`.
3. Add export download route handling both PPTX and PDF file types.
4. Test with `pytest tests/test_presentation_bridge.py`.
