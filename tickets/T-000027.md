## Goal
Enable zero-credit presentation generation across Google Gemini 3.1 and OpenRouter free models with batch-size rate throttling and template schema validation to prevent HTTP 429 rate limit errors and schema state machine overflows.

## Context & Problem
1. **Google Gemini Free Tier Rate Limits:** Google Gemini free tier allows 15 requests per minute. Presenton's default concurrency fired 10 slide generation tasks simultaneously via `asyncio.gather`, causing immediate HTTP 429 rate limit exceptions.
2. **Schema State Machine Constraints:** Templates with >20 layouts (e.g. `verdant`, `mosaic`, `editorial`) generate massive Pydantic schema unions that fail on Gemini's constrained decoding compiler with HTTP 400 (`too many states for serving`).
3. **OpenRouter Reasoning Token Exhaustion:** Reasoning models like `nemotron-3-nano-omni-30b-a3b-reasoning` generated verbose internal thought chains that exhausted output token limits mid-JSON, causing parse failures.

## Acceptance Criteria
- [x] Concurrency throttling: Patch Presenton slide generation loop (`presentation.py`) from `batch_size = 10` to `batch_size = 2` with inter-batch cooldown to stay strictly under 15 RPM.
- [x] Template schema compatibility mapping:
  - Google Gemini: Restrict/filter to compact templates (<=12 layouts: `Standard`, `General`, `Swift`, `Modern`).
  - OpenRouter: Unrestricted across all templates (`Verdant`, `Mosaic`, `Horizon`, `Civic`, etc.).
- [x] OpenRouter model optimization: Configure `nvidia/nemotron-3.5-lightning:free` as default free model for fast, structured JSON generation without reasoning cutoff errors.
- [x] Automated benchmark script (`scripts/test_presenton_generation.py`) supporting `--provider google|openrouter`, `--model`, `--template`, and `--slides` parameters.
- [x] Verified successful generation of 7-slide decks on both providers from scratch.
